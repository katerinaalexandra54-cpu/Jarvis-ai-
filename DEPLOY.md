# Deploying JARVIS (production setup)

The phone app never holds your AI key. A small server does, and the app proves itself to the server with a signed,
expiring token that it gets once by entering an access code.

```
Phone app --(access code, once)--> JARVIS server --> signs a device token
Phone app --(Bearer token)-------> JARVIS server --(your AI key)--> OpenRouter / OpenAI
```

## 1. Deploy the server (about 10 minutes)
The server is `server/` (Node + Express) and ships with a `Dockerfile` and `render.yaml`, so any Docker host works
(Render, Railway, Fly.io, a VPS). Check each host's current pricing and free-tier limits yourself.

**Render:** push this repo to GitHub, then Render > New > Blueprint > select the repo. In the dashboard set:
| Variable | Value |
|---|---|
| `OPENROUTER_API_KEY` | your OpenRouter key (stays on the server only) |
| `JARVIS_INVITE_CODES` | a code you invent, e.g. `blue-falcon-4821` (comma-separate several) |
| `JARVIS_TOKEN_SECRET` | auto-generated by the blueprint (or `openssl rand -hex 32`) |
| `ALLOWED_MODELS` | optional, e.g. `openai/gpt-4o,openai/gpt-4o-mini` |
| `DAILY_LIMIT` | AI requests per device per day (default 500) |

Test it: open `https://YOUR-SERVER/api/health`, you should see `{"ok":true,...}`.

## 2. Point the app at it
In GitHub: repo Settings > Secrets and variables > Actions > **Variables** > add `VITE_API` = `https://YOUR-SERVER`.
Re-run the "Build Jarvis APK" workflow. (The build fails on purpose if `VITE_API` is missing, so you never ship an app
with no way to think.)

## 3. First launch
Ask JARVIS anything. A box asks for your **access code** (the `JARVIS_INVITE_CODES` value). After that it just works.

## Everyday operations
- **Block a lost/stolen device:** add its id to `JARVIS_REVOKED` (ids appear as the token `sub`).
- **Change the AI provider/model:** change `AI_PROVIDER` / `ALLOWED_MODELS` on the server. No app update is needed.
  To add OpenAI: uncomment the `openai` entry in `server/ai.js`, set `OPENAI_API_KEY`, set `AI_PROVIDER=openai`.
- **Rotate everything:** change `JARVIS_TOKEN_SECRET`; every device must enter the access code again.
- **Developer builds only:** `VITE_ALLOW_DIRECT=true` lets you paste an OpenRouter key into the app. Never ship that build.

## Wake word ("Hey JARVIS")
1. Create a free account at console.picovoice.ai and copy your **AccessKey**.
2. In the app: Settings > Voice & Speech > paste the AccessKey > Save > switch on the wake word.
3. Settings > Phone Control > Allow permissions (microphone, notifications, location).
Optional custom phrase: train "Hey JARVIS" in the Picovoice Console (Android .ppn) and save it as
`android-bridge/assets/hey-jarvis.ppn`; the build bundles it automatically and the app uses it instead of the built-in "Jarvis".
Check Picovoice's current terms and limits for a product you plan to publish.
